Live demo · No signup How it works

Three promises we hold

These are enforced by an immutable Charter loaded at every session.

1. No auto-merge, ever

Laundry writes patches into a sealed bundle. It has no permission to touch main, no CI credentials, no push access. A human engineer signs — or it does not ship.

2. Evidence before edit

The updater agent refuses to run until the tests agent has produced a baseline suite the CURRENT code passes. You cannot prove a regression on top of broken tests.

3. Every claim needs a citation

LLM output that names a file or line must resolve to real content in the actual repo. Uncited claims are dropped by the judge agent before the reviewer ever sees them.

The 12 agents

Every session runs them in this exact order. Each has one job. Each writes into the sealed evidence bundle. Judge never writes code.

01

Indexer

Streams the repo, builds a software map + dependency graph.

02

Security

Nine secret patterns + dep-provenance probes (PyPI / npm / crates + OSV).

03

Business Rules

Extracts "when X → returns Y" claims with file+line citations.

04

Dead Code

Inverted symbol index. Every candidate carries ≥2 evidences.

05

Tests

Emits baseline characterization suites, executed in sandbox.

06

Updater

Proposes small patches. Cannot run without a passing baseline.

07

Parity

Applies patch to a sandbox worktree, diffs observed side-effects.

08

Architecture

Compliance with target-design rules.

09

Explainer ⭐

Before/after in reviewer's language, for every unit.

10

Passport

Owner (git blame), priority score, risk profile.

11

Documenter

Cross-module summary docs.

12

Judge

Reads the whole bundle, decides. Never writes code.
